What the evals found

Nine new eval cases covering meeting transcripts were added to the corpus. On the first run they scored 17 of 21. All four failures were real defects in the extraction engine, not bad test cases — spoken language breaks assumptions that written email does not. Each is fixed below, and the corpus now scores 21 of 21.

A word boundary made every plural invisible

fixed
- cues: /\b(…|competitor|incumbent|…)/i + cues: /\b(…|competitors?|incumbent|…|evaluation with)/i

\bcompetitor\b cannot match the word “competitors” — the boundary after the final r fails against the s. Any sentence using the plural scored as having no competitive objection at all. The eval case that caught it: “we are already fairly deep into an evaluation with one of your competitors.”

Spoken promises carry no listed action verb

fixed
"We will have the procurement paperwork back to you by the end of next week."

The commitment detector requires a modal plus an action verb. Here the verb is “have”, and the promise actually lives in “back to you” — a construction nobody writes in an email and everybody says out loud. The customer’s own commitments were being dropped. Added back to you, turn around and hand over as commitment phrases.

Product signals recognised asking, but not depending

fixed
"Unless the Salesforce sync lands before renewal I do not think we can justify keeping this."

The request cues covered “we need X” and “is there a way to X”, but not a feature gap expressed as a dependency — which is the commercially urgent form, because it is attached to a renewal. It scored as silence. Added unless, waiting on, still no, depends on and justify keeping.

Numbers said out loud were not numbers

fixed
"We are about four hundred people now, mostly in Manchester."

The fact extractor had no company-size rule, and its seat pattern required digits. In a transcript, quantities are words. Added a cardinal parser for spelled-out numbers up to 999,999, plus company-size and location rules. It returns null rather than a guess for anything it cannot parse — “quite a lot of people” produces no fact, which is the correct answer.

One fix then over-fired, and that is worth recording. Widening the request cues to catch “unless the sync lands” also made “we use Slack without any issues, it has been great” register as a Slack feature request — praise turned into a roadmap item.

It was caught by probing the change directly rather than trusting a green suite. without is now constrained to a determiner form (without a|an|the), and both directions are pinned as tests so the trade-off cannot silently reverse.

Edge cases

One rule runs through all of these: for input we cannot interpret, produce nothing, never a guess. A missed extraction costs a rep one manual entry; a fabricated one puts a false claim in the CRM, where an answer will later cite it as evidence.

The invariant under all of it

A meeting transcript is untrusted content. A customer can say anything into it, including an instruction. So the module that turns a meeting into CRM actions has exactly one exit, and it is the approval queue.

RuleHow it is enforced
Everything waits for a human Every proposal is written as a pending approval regardless of the tool’s own risk class. A test asserts dispatchTool is never called in that module.
Nothing malformed reaches the queue Each payload is parsed with the real tool’s Zod schema first; failures are discarded, not queued.
The approver sees the real effect Previews come from the registered tool’s own preview(), never a paraphrase — and the payload approved is the payload executed.
A transcript can never email a customer It may propose draft_email and never send_email. Asserted against the source.
Nothing reaches a real calendar by default CALENDAR_PROVIDER defaults to console, which delivers nothing. Live writes need it set and INTEGRATION_MODE=live.

Every screen

All 25 captured from the running application by scripts/capture-screenshots.mjs, signed in as the demo owner. Click any image to enlarge. The company names and figures are seeded demo data, not a real customer’s.

The first version of the capture script lied. It shot after a fixed delay, and produced three screenshots of closed dialogs that it reported as successes — the exact failure mode these documents usually ship with.

It now waits for the element it opened and records a failure if that element never appears. Chasing that down also surfaced two real bugs: the command bar’s own placeholder still said “Figbolt” after the assistant was renamed to Bolt, and <body> was missing suppressHydrationWarning, so browser extensions injecting isolation: isolate produced a hydration error.

Capture against localhost, not 127.0.0.1 — the dev server’s HMR socket fails on the raw address and the page never becomes interactive, so every click-driven capture silently produces a static page.
